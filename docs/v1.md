# COP31 Monitor V1.0: architecture, platform audit and release notes

Branch `v1-launch`. Static site on GitHub Pages, no framework, no database, no paid service, no API token in the page.

## Architecture

| Layer | Question it answers | Source | Who writes it | Where |
|---|---|---|---|---|
| Hoje na COP31 (Strategic Intelligence) | What matters? | `data/today.json` (published entries only) | Editor with `tools/today.py`; drafts stay in gitignored `editorial/drafts.json` | `#hoje` + top of Panorama |
| Atualizações (monitoring feed) | What did the agents collect? | `data/feed.json` | Monitoring agents → artifact → hourly sync to `main` | `#atualizacoes` |
| Pulso social (Social Pulse) | What are actors saying, raw? | Bluesky public API, live in the visitor's browser; `data/pulse.json` lists the accounts | Nobody: no processing | `#pulso` |

Raw posts never enter `today.json` automatically. `tools/today.py promote <feed-id>` copies only facts already in the feed into a **draft** in `editorial/drafts.json`, which is gitignored and so never committed, pushed or deployed. `publish` refuses until no `[preencher]`/`[revisar]` marker remains, a named human approves, at least one source is marked verified after being opened, and all six translations of the five substantive fields exist (or missing languages are declared in `i18n_pending`, which the page discloses). The validator rejects any non-published entry in `data/today.json`, and CI runs it. Draft preview works only on `localhost`/`127.0.0.1`; `?preview=1` on the public host does nothing and the page never requests `editorial/`.

### Files

- `index.html`: still the single page; new code is two blocks before the language boot (`Hoje na COP31`, `Pulso social`) plus changes in the feed block (status, retry, profile links).
- `data/pulse.json` (schema 2): public-safe export of the social watchlist (`tools/build_pulse.py WATCHLIST.json`). Each account carries `identity` (`checked` = handle read on the official page; `reported` = cited by a third party; `unverified`), the watchlist's own wording in `identity_basis`, `identity_evidence`/`identity_checked_at` (null until recorded), and, separately, account health (`health`, `health_checked_at`, `health_source`). Identity is never inferred from health or vice versa. Optional `bluesky_list` (an `at://…/app.bsky.graph.list/…` URI) switches Bluesky to one request; optional `x_list` `{url, name}` adds a list timeline; `hidden` holds post URIs or handles to suppress.
- `data/today.json`: schema in `tools/validate_feed.py` (`check_entry`). Ships **empty**. The two drafts prepared on 8 Nov live outside the repository (local `editorial/drafts.json` and a private Project doc).
- `tools/validate_feed.py`: schema checks for both files; `merge_feed.py` drops invalid items and refuses to write an invalid feed.
- `tools/merge_feed.py`: version-aware merge (`updated_at` › `first_seen`); older copies only fill missing fields.
- `tests/`: `test_feed_tools.py` (unittest), `test_v1.mjs` (jsdom), `fixtures/` (Bluesky responses); `tools/test_i18n.mjs` (all languages).

## Platform feasibility audit (8 Nov 2026)

| Platform | What works without a token | What V1 does | Limits |
|---|---|---|---|
| Bluesky | Public AppView API (`public.api.bsky.app`), CORS-open: `getAuthorFeed`, `getListFeed` | Native rendering: author, time, text with links/mentions/hashtags, images (real aspect ratio), link cards, quoted posts, video thumbnail, repost context, canonical post URL. Priority-A accounts by default; B on request. **Request limits per visitor:** at most 3 concurrent requests, 45 per load, 9 s timeout each, Refresh disabled 30 s after a load; a single 429 pauses all requests for 60 s. Load more by cursor with a merge boundary so slow accounts are never skipped. Labels `porn/sexual/nudity/graphic-media/gore/!hide` hidden and counted; `!warn` collapsed. **Fallbacks:** broken image or video thumbnail → 'open on Bluesky' link; broken avatar → initial; total failure or rate limit → profile cards linking to bsky.app | **Live API not tested from the build environment** (egress blocked). Rendering verified against one response captured live via the monitoring tool and synthetic responses of the same shape. Unauthenticated search is throttled, so search is not used. 35 accounts = 35 requests: create a Bluesky list and set `bluesky_list` to make it one |
| X | Official profile/list timeline widget (`platform.twitter.com/widgets.js`) | Account cards with profile links and the last two monitored posts; timeline only on click; persistent notice that empty timelines are an X restriction | Widely reported since 2023: logged-out visitors often see "Nothing to see here". The page cannot read inside X's iframe, so it cannot detect this; hence the notice. **Logged-out test must be done in a real browser** |
| Instagram | Single-post oEmbed/`embed.js` (tokenless since 15 Jun 2026); no account feed | Profile cards; monitored posts with a `/p/` URL can be embedded one by one on click | Today all monitored IG items in the feed link to profiles, so no embeds appear until the agent records post URLs |
| YouTube | Uploads playlist (`UU` + channel id) via `youtube-nocookie.com` | Player only on click, privacy-enhanced domain; 'loading' placeholder behind the frame and an always-visible link to the channel's videos (a blocked cross-origin frame cannot be detected) | Only 1 of 5 channels has a resolved `channel_id`; the others get a channel or search link, never a guessed id |

## Reliability changes (Sprint A)

- Feed status separates **collection** (web and social round times, "há N h", coverage, blocked list) from **page load** time; rounds older than 8 h (web) or 5 h (social) are flagged "atrasada".
- Coverage shows "c de t" when the round carries `configured`; agents do not send it yet (see pipeline).
- The Atualizações feed items still carry the monitoring agent's `verified` flag, which treats "reported" handles as verified; aligning the agent with the identity model above is a prompt change outside this PR.
- Loading → "ainda carregando" after 4 s → error with **Tentar de novo** after 20 s; a late success recovers.
- Social items whose URL is only the account profile are labelled "link do perfil" and the link reads "Ver perfil @x no X"; they are no longer presented as links to the post. No URL is invented.
- Publications show their source domain and when the monitoring recorded them.

## Two-stage monitoring pipeline (Sprint D, design only; not deployed)

Independent of the site: it changes only the scheduled-task prompts, so it can ship before or after V1.

1. **Stage 1, screening (Haiku, every run, whole watchlist).** Read each account/site, keep a per-source line in the run log (`ok / empty / blocked / error` with reason), and score each candidate 0–3 on source importance (watchlist priority), topic relevance (track keywords), novelty (not seen by url/id/text hash) and negotiation significance (presidency, blocs, ministers, text, decisions). Output: candidates with scores; no translation.
2. **Stage 2, analysis (Sonnet, only score ≥ 2 or priority-A official accounts).** Portuguese summary, tracks, `summary_i18n`, quotes. Anything that looks like a negotiating development is flagged `promote_suggested: true` for the editor; the agent never writes `today.json`.
3. **Coverage and gaps.** Each round writes `configured`, `attempted`, `sites_checked`/`accounts_checked`, `blocked`, `blocked_sites`. A source failing three rounds in a row is listed in the push notification; a round that cannot publish writes the existing pending doc.
4. **Dedup.** Key = canonical post URL when known; else `(platform, account, sha1(normalised text))`; publications by canonical URL without tracking parameters. Cross-platform mirrors (X ↔ Bluesky ↔ Instagram of the same account) are linked with `mirror_of` instead of being listed twice.

## Test fixtures

`tests/fixtures/` holds one **authentic** captured response (@enb.iisd.org) and **synthetic** responses for a fictional account on the reserved `.test` domain, every invented text prefixed `[TEST FIXTURE]` (see `tests/fixtures/README.md`). Invented text is never attributed to a real account. The page never requests anything under `tests/` (enforced by a test); a test also checks that no deployed data file contains fixture text or `<script`. Because the site is served from the repository root without a build step, the fixture files are reachable by direct URL, but nothing links to them.

## Production safeguards during development

- The hourly feed sync runs only in a separate worktree (`/home/claude/cop31-prod`) on `main`, refuses to run if that worktree is on another branch, commits only `data/feed.json`, and uses `main`'s own `merge_feed.py`. It never touches `v1-launch`.
- GitHub Pages serves `main` only; pushing `v1-launch` deploys nothing.
- Merging `v1-launch` will conflict only on `data/feed.json` if the sync has committed since; resolve by taking `main`'s file.

## Known limitations

- Bluesky live behaviour (CORS, rate limits, real timeouts) is untested here; first check after deploy is to open `#pulso` on a phone and a desktop.
- X logged-out experience untested; expected to fail often, which the UI states.
- `today.json` translations: entries carry `i18n` per language; none exist yet (no published entries). Translate after approval, never before.
- Fonts in screenshots fall back to system fonts (Google Fonts blocked in the test browser).
- `summary_i18n` and type labels translate the feed; titles, quotes and post text stay in the original language by design.
